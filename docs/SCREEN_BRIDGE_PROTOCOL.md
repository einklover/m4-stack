# M4 Screen Bridge Protocol

Android 无障碍屏幕桥 → Murphy M4 的局域网截图读取协议。手机端无障碍服务
截取当前画面，转成 1bpp 帧缓冲并在 **TCP 48624** 提供，M4 主动读取、解码后上屏。

## 角色与连接

- 手机：HTTP **服务端**，固定监听 TCP 48624。
- M4：HTTP **客户端**，发现手机 IP 后主动读取页面。
- 无 TLS、无认证，仅限可信局域网使用（见「安全说明」）。

## 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/status` | 状态 JSON（见下） |
| GET | `/v1/page?index=N` | 取第 N 页画面：24 字节 LE 头 + 载荷 |
| POST | `/v1/consume?index=N` | 通知 M4 第 N 页已被显示，可释放缓存 |
| POST | `/v1/tap?x=X&y=Y` | 实时模式下把 M4 逻辑坐标触摸转发给手机 |

## v2 结构化内容接口

v2 与截图协议共用 48624 端口，但传输可直接交给系统 XML 排版器显示的 UTF-8
JSON，而不是手机画面。当前首个适配器为小红书。手机是后台采集器，M4 是结构化
阅读器：手机会识别 Activity/页面、回到首页推荐、主动上下滑，并在卡片仍可点击时
进入图文笔记预取正文、首批评论和图片。M4 只展示已经整理完成的缓存，不要求手机
停留在同一画面。视频和直播卡直接过滤。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v2/apps` | 手机可启动应用目录；小红书标记为 `content`，其余暂为 `mirror` |
| POST | `/v2/apps/open?id=PACKAGE` | 在手机打开应用 |
| GET | `/v2/xhs/feed` | 已缓存完成的纯图文阅读清单；同时启动/继续后台采集 |
| POST | `/v2/xhs/feed/open?token=TOKEN` | 选择缓存笔记；无需手机当前仍显示该卡片 |
| GET | `/v2/xhs/note` | 当前笔记的标题、作者、正文、图片数和评论数 |
| GET | `/v2/xhs/image?index=N` | 第 N 张图片，480×650、1bpp BMP；优先返回预取缓存 |
| POST | `/v2/xhs/comments/open` | 打开缓存评论并在后台继续采集 |
| GET | `/v2/xhs/comments?advance=0|1` | 返回去重后的缓存评论；`1` 请求继续向下采集 |

`/v2/xhs/feed` 还返回 `state`、`activity`、`collecting`、`cached`、`discovered`
和 `target`，M4 可显示“手机后台采集中”而不阻塞已有缓存的阅读。token 由标题和作者
生成，在当前服务缓存期稳定；相同 token 始终指向已经预取的同一篇笔记。正文、评论
均来自无障碍节点，不读取账号私有数据库，也不会退回视频截图模式。

### 小红书页面状态机

1. `outside`：启动 `com.xingin.xhs`。
2. `home`：识别 `IndexActivityV2` 和推荐流锚点；必要时点“首页 → 发现 → 推荐”。
3. `note`：识别 `NoteDetailActivity` 及正文/图片锚点；向下滚动直到正文和评论出现。
4. `comments`：继续滚动、按作者和正文去重；完成后返回原推荐位置。
5. M4 选择文章时暂停推荐采集，直接切换缓存；请求未缓存图片或更多评论时，手机才在
   后台恢复对应笔记。页面识别同时使用 Activity 和多个语义 view id，避免依赖单一布局层。

### M4 排版约定

- 阅读清单：一行标题，第二行作者与点赞；只加入正文已缓存成功的图文笔记。
- 正文：标题作页面标题，作者/时间/图片数/互动数作灰度元信息，正文交给系统
  `flowText` 做电子书式分页；翻页不再操纵手机。
- 图片：单独的 480×650 图片页，手机侧缩放并 Floyd–Steinberg 二值化，左右切换。
- 评论：`序号 + 作者 + 时间/地区` 为小标题，正文连续排入 `flowText`，可本地分页；
  “更多”才触发手机继续采集。

### GET /v1/status

```json
{"ok":true,"port":48624,"active":true,"cacheEnabled":true,"captureErrorCode":0,"pages":{"lo":0,"hi":3,"count":4},"consumed":1,"connected":true}
```

- `active`: 手机端是否已开始截图会话。
- `cacheEnabled`: 当前有效模式；`true` 为缓存预取，`false` 为实时截图与触摸转发。即使用户打开了缓存，检测到广告、弹窗或非正文时也会暂时返回 `false`。
- `captureErrorCode`: 0 表示正常；正数为 Android 截图 API 错误，负数为本应用处理错误。
- `pages`: 手机缓存的最小/最大页索引和数量；`hi` 只是已抓取的最高页，不代表全书末页。
- `consumed`: M4 最近确认显示的页索引。
- `connected`: 最近 10 秒内是否有 M4 请求。

### GET /v1/page?index=N

返回 **24 字节小端头 + 载荷**。头字段（偏移 0 起，全部小端 LE）：

| 偏移 | 大小 | 字段 | 取值 |
|------|------|------|------|
| 0  | 4 | magic | 固定 ASCII `M4R1` |
| 4  | 1 | version | 固定 1 |
| 5  | 1 | codec | 0 = raw1，1 = custom RLE1 |
| 6  | 2 | width  | 固定 800 |
| 8  | 2 | height | 固定 480 |
| 10 | 2 | stride | 固定 100（每行字节数，800 px / 8） |
| 12 | 4 | page   | i32 页索引 |
| 16 | 4 | rawSize | 固定 48000 |
| 20 | 4 | crc32  | 解码后物理帧缓冲的 IEEE CRC-32 |

载荷随后紧跟：codec=0 时恰为 `rawSize` 字节原始帧；codec=1 时为 RLE1 流。
M4 校验 magic/version/codec/物理尺寸，解码后对帧缓冲计算 CRC 并与头比对，
任何不匹配都丢弃该页。

### POST /v1/consume?index=N

返回 JSON（HTTP 200）。手机收到后标记第 N 页已展示，用它决定继续预抓取并清理旧缓存。

### POST /v1/tap?x=X&y=Y

`X/Y` 是 M4 竖屏逻辑坐标（480×800）。手机按完整画面等比缩放、居中留白的几何关系映射到实际屏幕并执行点击；点击后等待画面稳定，重新截取实时第 0 页。该端点仅在 `cacheEnabled=false` 时接受请求。

## 帧缓冲布局（raw1）

- 物理尺寸 **800×480**，位图 **MSB 优先**，每字节 8 像素：
  **bit7 = 最左像素**，`1` = 白，`0` = 黑。
- 每行 `800 / 8 = 100` 字节，共 `100 × 480 = 48000` 字节（= stride × height）。

## 压缩：custom RLE1

token 高位置 1：

```
0b1_LLLLLLL  →  run 长度 = (LLLLLLL + 3)，随后跟 1 个重复字节
```

token 高位置 0：

```
0b0_LLLLLLL  →  literal 长度 = (LLLLLLL + 1)，随后跟该数量的原始字节
```

- run 长度范围 3…130；literal 长度范围 1…128。
- 解码结果必须恰好为 `rawSize`（48000）字节，否则视为坏帧。
- 手机端按「编码后载荷是否小于原始 48000」决定：**更小才用 RLE1，否则发送 raw**。
  随机/照片类画面 RLE1 反而膨胀，必须走 raw。

## 发现

沿用既有 Wi-Fi 传输访客表（`M4LanVisitorStore`）：手机曾在浏览器访问 M4 的
Wi-Fi 传书页后，其 IP 会出现在当前 SSID 的访客列表。屏幕桥活动取这些 IP 作为
手机服务器候选地址（优先最新），逐个尝试 48624 端口；成功地址会持久化供下次优先探测。

## 缓存行为

- 手机预抓当前页之后的 2 页，并保留至少 8 页历史画面。
- M4 另有 5 帧本地缓存（当前页及前后各 2 页）；触屏翻页优先切换本地帧，不等待网络。
- 本地缺页时 M4 后台请求，页面到达后自动切换，无需再次触摸。
- 用户关闭缓存后，手机只保留实时第 0 页；M4 触摸直接传给手机对应位置，待新截图到达后刷新。
- 缓存模式识别到广告、弹窗或其他非阅读画面时，会自动切换到上述实时模式，避免预取点击乱跳；重新识别到正文后自动恢复缓存预取和自动排版。

## 安全说明

- **无认证、无加密、明文 HTTP 帧**：同网段任意设备均可连接并读取画面。
- `/v1/tap` 可向手机注入触摸；这进一步要求只在可信局域网中运行。
- 仅在可信局域网启用；不要暴露到公网或不可信访客网络。
- 手机端只应在可信 Wi-Fi 中开启会话；路由器或系统防火墙不应把 48624 映射到公网。
